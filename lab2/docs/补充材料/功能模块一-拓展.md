# OS 获取可用物理内存范围：内存映射表与内存管理初始化

## 二、通过 BIOS 的 E820 接口获取内存映射表

在传统 x86 BIOS 启动环境下，引导程序（Bootloader）可以调用 BIOS 提供的 `INT 15h, EAX=E820h` 接口，获取系统的物理内存映射表。

内存映射表中的每条记录通常包含以下信息：

- **起始物理地址（Base Address）**：该段内存的起始地址。
- **长度（Length）**：该段内存区域的大小。
- **类型（Type）**：说明该区域是可用内存、保留内存，还是其他用途的内存。

例如，BIOS 可能返回如下内存布局（以下数据仅为示例）：

| 起始地址 | 长度 | 类型 | 含义 |
|---|---:|---|---|
| `0x00000000` | 640 KiB | 可用 | 常规低端内存 |
| `0x000A0000` | 384 KiB | 保留 | 显示设备等用途 |
| `0x00100000` | 511 MiB | 可用 | 可供系统进一步管理的内存 |

引导程序需要循环调用 E820 接口，逐条获取内存区域信息，直到取得完整的内存映射表。随后，引导程序将该表传递给操作系统内核。

## 三、操作系统如何判断哪些内存可以使用

内核收到内存映射表后，会根据每个区域的起始地址、长度和类型，识别可用物理内存，并排除保留区域以及已经被内核、引导程序等占用的内存。

例如，假设映射表中有一段可用内存：

- 起始地址：`0x00100000`
- 长度：`0x1FF00000`

该区域的结束地址（不包含结束地址本身）为：

```text
0x00100000 + 0x1FF00000 = 0x20000000
```

因此，该内存区域的地址范围为：

```text
[0x00100000, 0x20000000)
```

操作系统可以将这段内存进一步划分为大小为 **4 KiB** 的物理页，并交由物理内存分配器管理。

不过，内核不能直接把所有标记为可用的内存立即分配出去，还需要保留或排除以下区域：

- 内核代码、数据及其占用的内存；
- 引导程序及启动信息占用的内存；
- 固件或设备映射等保留区域；
- 其他当前不能安全分配的物理页。

完成这些处理后，操作系统就可以建立物理页管理结构，并由内存分配器按需分配和回收物理内存。

> **总结：** BIOS 通过 E820 接口提供物理内存布局，引导程序收集并传递内存映射表，内核再结合内存区域类型和自身占用情况，确定真正可供系统使用的物理内存。
